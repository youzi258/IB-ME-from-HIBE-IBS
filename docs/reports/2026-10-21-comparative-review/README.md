### 3.2 核心方法需要补上解释步骤

Sageloli部分至少要让读者跟上以下过程：

1. 采样在发钥或签名的哪一步使用，输入陷门、宽度等参数，输出什么对象。
2. 环元素展开成旋转矩阵后，哪些对象变大；写出对应维度和存储估算，注明它是按表示计算的估算。
3. 怎样保留多项式表示，通过变换把大运算拆成按频率的计算；画出变换前后对象形状。
4. 为什么只需对小矩阵分解；在这些对象和符号说明以后给出低秩平方根关系。
5. 怎样从计算计划得到新的随机样本，再检查模方程、范数和数值条件。

SRGG部分需要一个字段编码的具体例子，再汇总到四类对象及完整密文；Lai部分先画清“每条消息委派一次”和“会话开始委派一次”的操作差异，再介绍摊销公式。原语关键关系仍须解释，但按完整IB-ME实际使用它们的位置组织，避免五段高度压缩的算法摘要连续堆叠。

下面给出两段文风示例，数值沿用现有记录，尚未替换正文。

**Lai接收会话示例：** Lai方案中，接收者需要根据发送者身份，将一级密钥委派成用于解密的二级密钥。对于同一发送者的连续消息，这一步的输入保持相同。我们在会话建立时执行一次委派，保存经过校验的二级密钥，随后用它处理该身份对的消息。每条消息继续执行密文认证、解密和签名验证。使用一套主密钥的实验中，会话准备耗时509.55秒，后续解密中位数为28.57秒，额外保存约34.73 MiB的密钥数据。该方法适合固定双方连续收发消息；首条消息仍需承担准备成本。表注统一列出原路径2次、准备1次、会话内3次的测量次数。

**SRGG编码示例：** SRGG的JSON格式把每个多项式系数写成十进制文本，还需要分隔符和字段名。我们根据各字段的取值范围确定存储位数。例如，取值只有−1、0、1的陷门系数可用2 bit表示；签名中的短整数则根据实际位宽编码。解码后恢复原来的数学对象，并检查长度、取值范围和对象类型。三档参数下，主状态的编码长度降至原格式的约五分之一。实验应继续说明这项节省怎样影响密钥文件和完整密文。
