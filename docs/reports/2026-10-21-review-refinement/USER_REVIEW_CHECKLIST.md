### 16. Lai 会话摊销临界点

## 20B. 1.1、1.2 与第二章的待审核重写方向（本轮不改正文）

### 第一章应学习的组织方式

往届报告最值得学习的是：把“技术为什么重要、为什么选择该研究对象、现有研究缺什么、作品准备
解决什么”连成一条线。学习结构，不照搬夸张措辞、缺少来源的产业数字或技术错误。

1. **先建立值得研究的矛盾，再介绍技术。** 当前运维中心向受控终端发送指令的例子可以保留，
   但应继续回答为什么需要专门的身份匹配加密：IB-ME 将哪些身份条件纳入统一构造，匿名性保护
   什么，身份基机制改变哪些公钥发现与密钥分发环节。
2. **解释技术带来的变化，不只给定义。** 对业务端说明规范身份如何减少额外处理；对协议说明统一
   身份绑定和认证顺序解决什么组合问题；对公开信道观察者说明匿名 HIBE 的通信关系保护；对长期
   系统说明抗量子实现和可更换格后端的必要性。
3. **叙述逐步收窄，避免折返。** 建议顺序为：双方身份约束需求 → 现有组合方式的问题 → IB-ME
   与匿名性的作用 → 后量子迁移要求 → 格上实现的研究意义。匹配等式和四种情况表可精简或移到
   基础知识。
4. **研究现状先解释为什么选择多类格原语的完整 IB-ME 组合。** 不要一开始只罗列方案名称。
5. **介绍研究时同时讨论方法和代价。** 对每类 HIBE／IBS 说明解决了什么、实现成本在哪里、路线
   取舍是什么，以及为何引出本作品的采样、编码、委派和完整协议问题。
6. **让研究现状收束成问题。** 使当前 1.3 的四个问题——接口与对象差异、HIBE 容量与大签名、
   目标参数计算和存储、单次算法与连续服务差异——都能在 1.2 前文找到来源。
7. **不照搬往届技术错误。** 例如 CKKS 原论文是 ASIACRYPT 2017 的近似算术方案，不能照抄为
   2018 年“浮点数精确计算”。用户提供链接：
   <https://link.springer.com/chapter/10.1007/978-3-319-70694-8_15>。

建议用“时间线＋问题演进线”组织 1.2：

| 发展层次 | 需要说明的变化 | 如何引向本作品 |
|---|---|---|
| 身份基密码 | 身份如何参与加密和认证，分层委派解决何种管理需求 | 解释采用 HIBE 和 IBS |
| 身份匹配加密 | 双方如何分别指定对方身份，匿名性保护什么 | 解释 IB-ME 与通用构造 |
| 格上具体实现 | 不同原语的对象和计算方式有何差异 | 解释多类格后端选择 |
| 完整系统与优化 | 原语如何落实为消息流程，瓶颈出现在哪里 | 引出组合、采样、编码和会话 |

历史图应按真实关系绘制：HIBE、IBS 和格密码是并行支线，汇入通用构造和本作品；所有年份与节点
都要逐一核对。最终目标是使读者在读完 1.2 后能复述：已有 HIBE、IBS 和通用构造分别提供什么；
把它们变成目标参数下可运行、可保存、可比较的完整系统还缺什么；本作品具体解决哪些问题。
