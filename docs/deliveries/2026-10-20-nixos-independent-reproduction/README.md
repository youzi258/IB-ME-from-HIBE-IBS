# NixOS隔离安装与异机独立复现

本批在不同于原主力实验机的NixOS x86--64主机上，从固定源码快照导出干净源码树、构建wheel和原生引擎，并在源码树之外执行报告三组代表组合。目的在于核对“从安装包可恢复并完成完整协议”，不是增加可与原性能表混排的样本，也不重新评估底层安全证明。

## 复现边界

- 基线为主分支提交`018daf33a233a936719a7df9f50d1a776a1fee27`；执行源码提交`814e85bb50fb3bf596cd69ba6f51ee5d53ba5f9b`仅增加本机工具链构建支持，不改变算法、Suite或历史原生源码标识。
- wheel摘要为`e5fab799b548a79f18a19bb33dfeadc7bf0b3019766b4342ba257fe5f3c82cbe`；安装后的604个文件已重新核对，运行时模块搜索路径不包含源码树，全局Python／Sage环境未被修改。
- LATTE、ML-DSA-44与Sageloli均从同一源码快照使用本机工具链构建；受版本控制的文件不含Nix store绝对路径。第一次LATTE编译在密码运算开始前因Nix编译器包装器移除`-march=native`失败，随后只在该显式本机构建步骤取消相应限制；失败日志在仓库外保留。
- 第一次拆分长阶段时曾误用不含Sage Singular运行库的普通Python，导入阶段即失败，未开始密码运算、未生成命令记录且未改变状态；随后改为本机Sage的`-python`入口。该调用修正不计作功能失败或成功样本，但在构建来源中保留。
- A、B、C均绑定当前冻结的完整Suite，分别为`secure/true/true`；这沿用项目对已完成方案的安全说明。功能复现不替代论文论证，不构成NIST认证或新的安全等级评估。
- 密钥、签名及封装随机性均来自操作系统CSPRNG，没有固定秘密种子或为成功样本重选随机流。私有状态、原始标准输出／错误输出和详细命令日志只保存在仓库外。

## 结果

| 代表 | 新根 | 诚实应用消息/B | 本批实测最大wire/B | 功能范围 | 结果口径 |
|---|---:|---|---:|---|---|
| A：LATTE＋BNN/ML-DSA-44 | 1 | 0／32／1024／59191 | 201243 | 25条独立解释器命令，含往返、容量与身份边界、三种身份错配、四种wire篡改、有效外层／无效内层及恢复 | 一次整套执行通过 |
| B：LATTE＋SRGG PARAM-I compact | 1 | 0／32／1024／65364 | 214539 | 同A的25条矩阵 | 一次整套执行通过 |
| C：Lai C2＋Sageloli PARAM-I | 1 | 0 | 4555404 | 建立、发钥、加密、四种wire篡改、诚实解密、有效外层／无效内层及恢复 | 功能通过；资源时间盒调整完整披露，不算一次执行验收 |

A、B每条命令均启动新解释器；同身份重复发钥不改变状态，新进程恢复没有重做建立、发钥或签名，恢复前后持久状态摘要不变。四个消息长度都实际完成加密与解密，应用容量加1和身份长度加1均在预检阶段拒绝。

C的建立、发钥和加密约需分钟级，真实Lai委派占解密主体。最初完整流程给每个worker 900秒、总流程1800秒，前置阶段用掉大部分总预算后，诚实解密被资源时间盒终止；第一次拆分出的诚实解密仍在900秒达到上限。两次失败状态中的故障关闭（fail-closed）标记均原样保留，没有删除标记后继续使用失败状态。随后从加密完成时已预先保存的同一根干净状态复制三份，分别执行诚实解密、有效外层下的无效内层签名负例和新进程恢复；每阶段上限放宽到3600秒，没有重新建立或重新发钥。因此C可以作为同一密码根上的功能复现，但不能标成“首次一次执行通过”，也不是重复性能基准。

| C成功拆分阶段 | 单次墙钟/s | 实际密码路径 |
|---|---:|---|
| 诚实解密 | 1308.931756 | 1次Lai Derive，Sageloli验签为真，恢复空消息 |
| 有效外层／无效内层 | 1631.867366 | 1次Lai Derive，Sageloli验签为假并返回拒绝 |
| 新进程恢复解密 | 1283.917410 | 1次重新随机化的Lai Derive，Sageloli验签为真，状态不变 |

三个worker有部分并行且每项只有1次，秒数只用于说明900秒时间盒不足；不能相加成总运行时间，也不进入性能排名。

Wang IBS不在本批范围内：其现有组合流程超过一小时且私钥与内存需求明显更高，相关测试来自另租服务器；它不影响已经固定的A、B、C三组报告代表。

## 公开文件

- [A.json](A.json)、[B.json](B.json)：25条命令的脱敏公开摘要、长度／wire观测、状态边界和provider摘要。
- [C.json](C.json)：C的已完成前置阶段、两次资源超时、三条成功拆分阶段与同根状态承诺。失败历史是结果的一部分，不将延长时间盒伪装成首次通过。
- [environment.json](environment.json)：主机与本机工具版本；[build.json](build.json)：源码、wheel和原生引擎构建来源。
- [build_c_public.py](build_c_public.py)：仅用于从仓库外私有C记录生成脱敏摘要；公开复核不需要私有输入。
- [verify.py](verify.py)：只读校验公开文件和三份冻结Suite，不读取私有状态、不重跑密码实验；[verification.json](verification.json)保存本批实际复核结果。

仓库根目录执行：

```text
git ibme-run python3 docs/deliveries/2026-10-20-nixos-independent-reproduction/verify.py --self-test
```

本批实际通过72项公开文件／范围检查。校验器还执行六个篡改负例，分别改变A的wire尺寸、B的内层拒绝、C的重试口径、C的超时历史、C恢复阶段的随机委派和wheel摘要；六项均被拒绝。
