## 3. 根近均匀、委派与签名条件

### 3.1 根 GenTrap 与 A 的分布

**原文事实。** W p.7 Lemma 2.5、p.16 要求 TrapGen 输出近均匀 A。MP12 p.24 Algorithm 1 构造 `A=[Abar | HG-Abar*R]`；统计实例分别要求 R 分布的 subgaussianity 和 `(Abar,Abar*R)` 的 regularity，不能只验 `m>=2*n*k` 就结束。MP12 p.12 Lemma 2.4 给出现有有限充分条件，p.24 还明确引用 leftover hash 方式核 regularity。

**代码。** [`backend.py`](../../../src/ibme/ibs/wang_pw_target/backend.py):122–137 均匀生成 Abar，调用有限整数 Gaussian 生成 R，检查 signed16 范围后构造 A，并用数值 QR 的根 GS 门接受/拒绝。精确关系为 `A*[R;I]=G`。W p.7 文字使用相反的 `[-R;I]` 陷门符号；本实现对应原文陷门的负号，必须一直保留同一约定。

**剩余证据。** 为 `s0=4,m_bar=16384,w=16384` 选定根分布误差预算，代入现有 regularity/leftover-hash 条件，记录跨 w 列累计与有限一维 Gaussian 误差。可评估离散 Gaussian 的一维碰撞质量并套现有 leftover-hash 引理；这是既有结果的有限代入候选，本文未计算出准入回执。不能因某个平滑充分界不满足就称根分布已不安全，也不能因维数条件满足就称 regularity 已完成。另须将根 GS 门、编码门接受/中止与无条件 GenTrap 分布分开记录。

### 3.2 委派用户 X

**原文事实。** W p.8 Lemma 2.7 和 p.16 要求 DelTrap 宽度 s 相对主陷门质量足够大；输出用户 G-trapdoor。W p.7 Lemma 2.6 为 SamplePre 给出 `s>=sqrt(s1(R)^2+1)*||S_tilde||*omega(sqrt(log n))`。这些渐近符号没有替本档给出有限乘数8。

**代码。** `backend.py`:139–163 按列执行 `X_j <- GPV(A,(G-H1)_j,s_del)`，用户密钥只含公开 A、自己 X、身份与固定盐。`SigningKey` 在 [`objects.py`](../../../src/ibme/ibs/wang_pw_target/objects.py):215–234 精确检查 `A*X+H1=G (mod q)`。因此 `F=[A|H1]` 满足 `F*[X;I]=G`。主基/主陷门没有作为用户钥交付。

**实现路线。** [`math.py`](../../../src/ibme/ibs/wang_pw_target/math.py):94–127 采用 MP12 p.23 Lemma 5.3 的完整核基转换，再执行 GPV/Klein；不是 MP12 perturbation Algorithm 3。MP12 Lemma 5.3 的适当列序、gadget 基及范数条件须对应实际 builder。`math.py`:130–146 使用 SciPy float64 economic QR。代数核基与精确方程成立，不自动认证浮点 GS 或采样输出分布。

**剩余证据。** 核对完整基的列序/整格基条件；给定被接受根的真实 GS 包络及浮点误差处理，再引用 GPV p.14 Theorem 4.1、p.17 既有误差计算，将每列 GPV 距离按 w 列和查询总量累计。用户 X 的 signed32 门、中心/整数资源门和后续用户 GS 拒绝须列入失败表。已有小规模/一次根测试只能作为实现证据。

### 3.3 签名与用户 GS / 范数

**原文事实。** W p.16 使用 `SamplePre(F_id,T_id,H2,s')`，验签同时检查非零、方程与公开范数。GPV pp.14–17 给出从完整基采样的既有条件和误差分析；一维有限充分参考为

```text
eta_epsilon(Z) <= sqrt(ln(2*(1+1/epsilon))/pi).
```

当每个真实条件 rho 宽度至少8时，可对 epsilon 作有限代入；还须计入归一化因子、全坐标和全查询数，不把“乘数8”本身当整链认证。

**代码。** `backend.py`:165–204 仅用公开 A 和用户 X 重建用户基，检查其数值 GS 不超过 `g_user`，新取消息盐，按 `s_sig` 调用原生 GPV；最终验证不通过则中止，无隐式重抽。`backend.py`:56–65、218–229 使用 Python 整数范数与精确模 q 方程验签。`g_user` 只在 Sign 准备阶段核查，不应把成功 Extract 说成已通过用户 GS 门。

**剩余证据。** 目标独立签名和恢复签名实际成功；用户 GS/浮点中心误差的有限处理；引用现有离散 Gaussian 尾界为诚实签名超过公开范数门分配失败预算。`B_verify` 是固定的攻击者可提交范数上界，不能事后改成某次实际签名范数。本文没有改其数值。

## 4. 有限采样与所有中止预算

[`native.py`](../../../src/ibme/ibs/wang_pw_target/native.py):1–10、276–307 和 [`native/gaussian.cpp`](../../../src/ibme/ibs/wang_pw_target/native/gaussian.cpp) 给出真实实现：

```text
weight(x) = floor(2^192 * exp(-((x-c)^2-dist(c,Z)^2)/(2*sigma^2)))
window    = floor(c) +/- (ceil(20*sigma)+1).
```

这是真正按整数权重抽取的有限离散 Gaussian，不是连续正态后舍入；仍不能直接等同于无限精确 `D_Z,s,c`。GPV 的一维 rho 宽度应按 `s_i=s/||b_i*||` 映射，代码实际标准差为 `sigma/ sqrt(norms[i])`（C++:300–303），其中 norms 为浮点 GS 长度平方。

## 5. PW 哈希、盐与查询损失

**原文事实。** PW p.12 Figure 5：`id'=J_id(id,r)`，`m'=J_msg(m,salt_msg)`；外层消息哈希不带身份。W Figure 4 的内部 `H1(mpk,id')`、`H2(mpk,id',m')` 则绑定身份和根。PW p.12 Theorem 2 的 ROM 损失为

```text
Delta_PW <= (Q_C+2*Q_S)*Q_H/2^ell
            + Q_C/|ID| + Q_S/(|ID|*|M|).
```

`Q_H` 包含发钥/签名间接引发的哈希查询；不能只数攻击者显式API次数。

**代码。** `hashing.py`:13–27、54–75 有四个独立域、规范长度前缀；两个外层输出各256 bit，盐各256 bit，基础 H1/H2 绑定规范公钥 SHA256 上下文。完整参数快照含 threads；不得修改既有钥快照的线程数字再声称仍是同一哈希上下文。身份最大字节数/单次消息容量不是查询上限。

**剩余证据。** 冻结有限 `Q_C/Q_S/Q_H`（包括长期服务和内部调用），将 `ell=256,|ID|=|M|=2^256` 代入上述现有界；明确 SHAKE256/公钥摘要实例化的研究假设和 ROM 范围。不能以256 bit字段长度直接给出 NIST 类别或量子哈希查询归约。

**固定服务的工作假设。** PW p.8 Figure 1 的 Sig oracle 每次先 KeyExt；本项目 FixedIssuer 按身份固定同一用户钥/身份盐。PW Figure 5 算法支持对既有 `(r,sk')` 重复签名，但该事实不等于 Figure 1 的重新发钥转录已经覆盖持久固定服务。依据当前 AGENTS，将相应服务安全对应明确列为工作假设，引用范围与工程恢复测试分开；不恢复旧报告中另补完整归约的任务。本档不以新证明阻塞服务工程，也不把服务导入解释成认证原始生成分布。

## 6. 正确 SIS 输入与当前拒绝范围

### 6.1 必须使用委派宽度 s，而非根宽度 s0

W pp.17–19 的模拟矩阵是

```text
Rhat <- D_Z,s^(m x w),   s=4096（当前委派rho宽度）
z_ref <- D_Z,s'^(M),     s'=8388608
z_SIS=[I_m|Rhat]*(z_forged-z_ref).
```

`Rhat` 不是主陷门 R（`m_bar×w`、宽度 `s0=4`），也不是一次实际用户 X 的观测样本。不能把4代入其谱界，不能漏掉维数、条件化分布和失败预算。

若已有覆盖所需概率/查询事件的统一 `L_Rhat` 与 `B_ref`，现有代码按原文提取的范数不等式计算

```text
beta_SIS = ceil((ceil(B_verify)+B_ref)*sqrt(1+L_Rhat^2))
SIS input = (n=512,m=32768,q=4294967291,norm=2,beta=beta_SIS).
```

对应 `params.py`:229–249。m 是根A列数，不是 M=49152。两个输入须有来源和失败预算，不能填一条实际签名范数或一次矩阵谱测量；`parameter_audit.py`:129–165 只换算、不认证调用者来源。

### 6.2 离散谱常数的引用边界

W p.7 Lemma 2.3 写通用常数 C 很接近 `1/sqrt(2*pi)`；其来源 MP12 p.14 Lemma 2.9 给出的定理是“存在通用 C>0”。MP12 紧接的文字将离散 Gaussian 的接近值标为 **empirically**；明确的 `C<=1/sqrt(2*pi)` 是针对 iid **连续** Gaussian。不能把经验常数当成本后端离散 `Rhat` 的已证有限上界。后续应选有数值常数与失败概率的现有保守界作有限代入；没有来源就保留缺口，不以实验拟合替代。

### 6.3 已发生的输入拒绝

当前配置参考包络 `B_ref=ceil(B_verify)`、即使乐观取 `L_Rhat=1`，得到

```text
beta=5260239171 >= q=4294967291.
```

[`evidence/local/parameter-screen.json`](evidence/local/parameter-screen.json) 已真实调用冻结 estimator `53da5982597709ba0fdf94ea37a84d822310fd84` 的 `SIS.lattice(...,norm=2)`，收到 `SIS trivially easy. Please set norm bound < q.`。`q*e_i` 已是该输入下的平凡 SIS 解。**这不是“尚未运行estimator”，也不是当前 IBS 被本文件证明可伪造；它拒绝的是明确配置的归约参数包络。**

同份回执保留 `uniform_beta_established=false`、`reference_envelope_justified_uniformly=false`、`all_tighter_reference_envelopes_ruled_out=false`。不能将该拒绝夸大成一切更紧包络均不可能；同样不能把“也许存在更紧界”写成可安全交付的当前参数。
