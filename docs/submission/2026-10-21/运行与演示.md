# 运行与演示说明

## 环境

密码算法在Linux／WSL的SageMath环境执行。已有记录覆盖Sage 10.7、10.9，Python 3.12／3.13，以及另一台Sage 10.9／Python 3.14的NixOS主机；各批精确版本保存在对应JSON中。Windows可阅读文档、截图和JSON，密码运算使用WSL。

本包提供项目源码和Python wheel。运行环境另需Sage、NumPy、cryptography 49或50、GCC/G++；原生构建需GMP、MPFR、MPC、OpenSSL开发文件，C方案另需FLINT和OpenMP。默认构建器从`~/miniconda3/envs/sage`读取头文件及库。wheel是项目的Python安装包，不包含Sage环境或可跨机器直接复用的原生二进制。

## 安装与启动A／B演示

将`01_程序源码`和`05_安装文件`复制到同一Linux目录下，建议放在Linux文件系统，进入源码目录。在已经安装的Sage环境中执行：

```sh
source "$HOME/miniconda3/etc/profile.d/conda.sh"
conda activate sage
export PYTHONUSERBASE="$HOME/.local/share/ibme/dependencies"
python -m pip install --user 'cryptography>=49,<51' pytest setuptools
bash experiments/run_web_demo.sh --build-native \
  --wheel ../05_安装文件/ibme-0.1.0-py3-none-any.whl --port 8765
```

最后一条命令构建LATTE、ML-DSA和Falcon原生桥并启动本地服务。已有对应构建时省略`--build-native`。浏览器打开`http://127.0.0.1:8765`。

NumPy使用Sage环境已配套的版本，不在此步骤另外升级。

复用已有环境时，以页面实际预检结果为准。安装命令需要获取未安装的依赖；依赖版本及原生构建来源与本项目的源码安装包分别记录。

## 页面操作

1. 选择方案A，输入发送者Alice、接收者Bob，点击“开始演示”。
2. 输入消息并点击“加密消息”。选择“双方身份正确”，点击“解密验证”，应恢复原文。
3. 在“验证情形”中分别选择发送者错配、接收者错配、双方错配、篡改1 bit或截断1字节，点击验证，查看实际拒绝结果。
4. 切换“运行记录”查看操作表，点击“导出JSON”保存本次会话的参数、尺寸、耗时及结果。
5. 如需方案B，结束当前会话，选择B重新开始。B使用固定的SRGG论文PARAM-I、compact编码与128 KiB载荷预算。

执行中刷新会重连原任务。服务退出或重启后，Web内存会话清空；需要持久状态时使用CLI。截图中的时间属于当次操作，不代替归档的多根性能基准。

## 方案C的额外原生依赖

在源码目录中先构建Sageloli环原生库，将其实际输出路径写入`IBME_SAGELOLI_RING_NATIVE`，再启动Web：

```sh
mkdir -p "$HOME/.cache/ibme-native-tools/sageloli"
python -m experiments.research.candidates.sageloli.ring.native \
  --directory "$HOME/.cache/ibme-native-tools/sageloli" \
  > "$HOME/.cache/ibme-native-tools/sageloli/build.json"
```

构建输出JSON中的`path`是本机库路径。例如，可用下面的命令读取该字段：

```sh
export IBME_SAGELOLI_RING_NATIVE="$(python -c 'import json; from pathlib import Path; print(json.loads((Path.home()/".cache/ibme-native-tools/sageloli/build.json").read_text())["path"])')"
bash experiments/run_web_demo.sh \
  --wheel ../05_安装文件/ibme-0.1.0-py3-none-any.whl --port 8765
```

C采用Lai C2与Sageloli v3 PARAM-I，应用消息容量3924 B。建立、发钥和真实委派属于长操作，页面显示当前阶段；现有完整C记录主要来自CLI和异机复现，不能用Web预检替代完整运行。现场可先演示A/B，再结合C的公开数据说明目标规模与状态成本。

## CLI与测试入口

以下A配置使用新的状态目录，后续命令自动恢复其冻结选择：

```sh
python -m pip install --user --no-deps ../05_安装文件/ibme-0.1.0-py3-none-any.whl
export IBME_LATTE3_EXECUTABLE="$HOME/.cache/ibme-native-tools/demo-runtime-v1/latte/bin/ibme-latte3"
export IBME_CERTIFIED_SIGNATURE_BIN_DIR="$HOME/.cache/ibme-native-tools/demo-runtime-v1/mldsa/bin"
printf 'Meeting at 15:00.' > message.bin
python -m ibme.cli setup --state demo-state \
  --hibe latte --hibe-params seed32 --ibs cert-ml-dsa \
  --ibs-params ml-dsa-44 --transport hybrid \
  --protocol byteauth-v1 --signature-format reference
python -m ibme.cli issue-sender-key Alice --state demo-state
python -m ibme.cli issue-receiver-key Bob --state demo-state
python -m ibme.cli encrypt --state demo-state --sender Alice \
  --receiver Bob --in message.bin --out message.ct
python -m ibme.cli decrypt --state demo-state --sender Alice \
  --receiver Bob --in message.ct --out recovered.bin
```

CLI需要显式继承已构建的原生引擎路径，详见同目录的环境路径表。`demo-state`为新运行生成的私有状态，不属于公开附件。

附带源码中的`tests/`是测试代码，`ci/`是测试清单。快速Web回归可在源码根运行：

```sh
python -m pytest -q -p no:cacheprovider \
  tests/test_webui.py tests/test_webui_jobs.py tests/test_webui_http.py
```

部分历史研究审查测试需要另外获取论文PDF或对应归档证据；本支撑包提供主要源码、测试和报告所用数据，不将这些额外缓存计为已随包分发的运行依赖。

| 环境变量 | 内容 | 默认位置 |
|---|---|---|
| `IBME_LATTE3_EXECUTABLE` | LATTE桥可执行文件 | `$HOME/.cache/ibme-native-tools/demo-runtime-v1/latte/bin/ibme-latte3` |
| `IBME_CERTIFIED_SIGNATURE_BIN_DIR` | ML-DSA桥目录 | `$HOME/.cache/ibme-native-tools/demo-runtime-v1/mldsa/bin` |
| `IBME_CERTIFIED_FALCON_BIN_DIR` | Falcon桥目录 | `$HOME/.cache/ibme-native-tools/demo-runtime-v1/falcon/bin` |
| `IBME_SAGELOLI_RING_NATIVE` | Sageloli环原生库 | 以上构建JSON的`path` |
